# Research refine (FarField)

Adapted from ARIS `/research-refine`. The product loop is already `idea_rounds` on the same pair plus neighbourhood continue. This skill is intern guidance, not a second discovery ring.

Problem Anchor = the mission topic's object phrases. The far-field node is a mechanism. `pair[0]` must remain a covering label (`label_covers_topic`) or the researcher's own phrase — not `definite program` because it shares `program`.

Keep:

- the bound task world (`WORLD.md`), except a GENERATED world that never contained the object (`object_absent`): adapt that fixture in place (`adapt_world`)
- this pair's H (Memory / Skills / Tools / Verifiers / Routing)
- `claim-domain-lock`

Change only:

- the text a text gate killed
- a `no_handle` death (same pair against the scouted lever table)
- one compile rewrite after diagnosis + world-sim when rehearsal named a structural hole (`duty=compile`)
- one pre-registration rewrite when `critique_card` named `must_change` (same pair; opinion with a rewrite budget, not a kill)

Keep `idea_kind` of the parent on a gate refine. Do not rewrite a question or acquire card into a dropout probe. Do not rename the scientific object. Do not switch the far concept. Do not rebind Pride. Two `uninformative` results in this mission — WORLD or GENERATED — switch the lever now; that is experiment iteration, not a new generate. A GENERATED `uninformative` or an `object_absent` does not occupy the spray seat. An acquire card is not an uninformative probe.

Do not open sibling `ideas/` folders. Do not start a new far jump to make this idea look nicer.
